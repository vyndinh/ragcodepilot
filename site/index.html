ENGINEERING DECISIONS

Explore the foundational algorithms and engineering decisions that power high-precision code retrieval.

Go AST Function-Level Chunker

internal/ingest/chunker_go.go
STRUCTURALLY AWARE

Parses the full Go abstract syntax tree using go/parser. Extracts complete function declarations, method receivers, signatures, and doc comments as a single cohesive unit without arbitrary split boundaries.

// AST Chunker extracts complete logical units: // - Package name // - Docstring comments // - Method receiver (e.g., (c *Client)) // - Function name & signature // - Full function body from { to } // - Result: Zero broken syntax or severed scopes!

Generic Sliding Window

internal/ingest/chunker.go
GENERIC FALLBACK

Used for languages without dedicated AST parsers (Python, TypeScript, Shell). Slices files into 40-line windows with a 5-line overlap, using regex heuristics to extract surrounding identifiers.

// 40-line sliding window + 5-line overlap (DefaultChunkLines/DefaultChunkOverlap) // Regular expression fallback identifies: // - func / def / fn definitions // - Prevents functions from losing context across window cuts // - Overlap ensures queries near boundary match

Raw Code Chunk

Before Enrichment
RAW TEXT

Embedding raw code without context leads to false positives when functions use common verbs or variables like Search or Init.

Enriched Embedding Input

internal/ingest/enrichment.go
STRUCTURAL CONTEXT

Prepending file location, repository, and signature metadata to the text before vectorizing gives symbol-navigation queries like "Qdrant collection setup" an exact-text anchor — this is what lifts navigation hit rates.

file: internal/qdrant/client.go package: qdrant function: (*Client).EnsureCollection language: go --- func (c *Client) EnsureCollection(ctx context.Context, name string) error { ... }

Why Hybrid Search? Reciprocal Rank Fusion (RRF) with k=60

Dense vector embeddings excel at semantic similarity (e.g. matching "how does chunking work?" with ChunkFile), but struggle with exact symbol navigation (e.g. "SearchWithTimings"). BM25 keyword matching is the exact opposite. RRF fuses them without needing fragile score calibration:

Score(chunk) = Σm ∈ {dense, sparse}   [ 1 / ( 60 + Rankm(chunk) ) ]
DENSE COSINE

Ollama 768d vector captures natural concepts, high-level intent, and synonyms.

SPARSE BM25

Snowball-stemmed keyword matching pins exact symbols and function names.

SERVER-SIDE RRF

Executed natively inside Qdrant in a single gRPC call with zero client overhead.

Incremental Reindexing & SHA-256 Change Detection

Embedding 200,000 code chunks at ~50ms each takes 30+ minutes. ragcodepilot avoids redundant work using a two-tier change detection algorithm:

1. SHA-256 HASHING

Each file's SHA-256 is compared with Qdrant payloads. Unmodified files skip chunking and embedding entirely.

2. INDEX VERSIONING

When chunker logic or enrichment schemes change, bump index_version to trigger a clean selective refresh.

3. FSNOTIFY WATCH DAEMON

ragcodepilot index --watch . listens to filesystem events, debounces writes, and upserts changed files in real time.
